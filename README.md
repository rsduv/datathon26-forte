# Контроль кассовой дисциплины по видео — DATATHON'26, кейс ForteBank

Локальный AI-сервис: загружаете видеозапись кассы (.mov) → получаете вердикт, список возможных нарушений
с таймкодом, кадрами-доказательствами, описанием увиденного и ссылкой на пункт норматива РК.
Результат — **подсказка проверяющему**, а не юридическое заключение.

## 1. Адреса и доступ
| Что | Значение |
|---|---|
| Веб-интерфейс | `https://<будет после деплоя>` |
| API | `https://<будет после деплоя>/api/v1` |
| API-ключ | передаётся жюри отдельно; заголовок `X-API-Key` |

## 2. Как пользоваться
**Интерфейс:** открыть адрес → перетащить .mov → «Проверить» → статус «Анализ… N с» → результат:
«Нарушение не обнаружено» или «Обнаружены признаки возможных нарушений: K» с типом, таймкодом, описанием, нормой и кадрами.

**API (два шага, как в ТЗ):**
```
curl -X POST https://<адрес>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
# → {"job_id": "3f2a9c1e", "status": "processing"}
curl https://<адрес>/api/v1/jobs/3f2a9c1e -H "X-API-Key: <ключ>"
# → {"job_id": "...", "status": "done", "verdict": "violation"|"no_violation", "violations": [...]}
```
Без верного ключа — `401`. Каждое нарушение: `type`, `timecode_sec`, `description`, `evidence_frames` (1–3 JPEG в base64).
Обработка видео ≤ 5 мин: на GPU (ноутбучная RTX 3050) 1–13 с на видео, на CPU примерно 20–90+ с.

**Локальный запуск:** `service\run.bat` (Windows) или
`cd service && pip install -r requirements.txt && uvicorn app:app --port 8000`; Docker — `service/Dockerfile`.

## 3. Архитектура и подход
```
UI / API (FastAPI, X-API-Key) → очередь задач → кадры 1 fps (≤ 600 на GPU, ≤ 60 на CPU — тогда реже 1/с)
   → детектор объектов (люди, ноутбук, стол, сумки) → фильтры (отражения в стекле, дубли)
   → правила по объектам, зонам и времени (+ OWLv2: деньги и стакан на столе) → события → описание по шаблону + норма → JSON
```
- **Модель:** Faster R-CNN MobileNetV3 (torchvision, лицензия **BSD-3**, веса COCO). Работает на CPU, GPU подхватывается сам.
- **Вторая модель:** OWLv2 (Google, `google/owlv2-base-patch16-ensemble`, лицензия **Apache-2.0**) — находит предметы по текстовому
  описанию, которых нет среди классов детектора. Медленная (~5 с/кадр на CPU), поэтому запускается точечно и не дольше 90 с на видео:
  - «пачка купюр» — на 3 кадрах вырезки стола в момент прихода **каждого следующего** клиента (деньги прошлого клиента на столе);
  - «стакан кофе» — на вырезке стола раз в 2 с, срабатывает, если стакан виден устойчиво (медиана 3 замеров); если стол
    не найден (другой ракурс) — смотрим весь кадр с более высоким порогом.
- **Почему правила, а не end-to-end модель:** 42 обучающих ролика (40 уникальных), тип нарушения не размечен, финальный ракурс другой.
  Правила поверх детекций объяснимы (видно, *почему* сработало) и не требуют обучения на данных заказчика.
- **Почему не LLM/VLM:** локальные мультимодальные модели на CPU — ~17 с на вопрос и неверные ответы (проверяли SmolVLM);
  описания строим **по шаблону из того, что реально обнаружено** — без выдуманных деталей.
- **Почему не YOLO от Ultralytics:** лицензия AGPL-3.0 несовместима с коммерческим использованием (FAQ п. 24, 34).
- **Локальность:** все модели внутри контейнера; после загрузки весов интернет не нужен; облачные AI-API не вызываются.
- **Лица не распознаются:** детектор возвращает только класс «человек».

## 4. Распознаваемые типы нарушений
Поле `type` в JSON — код в скобках; заголовок и норматив — как их возвращает API (`service/rules.py`).

| Тип | Что видит сервис | Норматив |
|---|---|---|
| Рабочий компьютер оставлен незаблокированным (`computer_unlocked`) | кассир покинул кадр, экран ноутбука светится открытым рабочим окном | Требования к ИБ банков (АРРФР № 53 от 03.04.2026), п. 53, п. 71 пп. 9 |
| Кассир покинул рабочее место, оставив наличные без хранения под замком (`left_unattended`) | кассир ушёл, на столе осталась инкассаторская сумка | Правила кассовых операций (НБРК № 231 от 29.11.2019), п. 20 (ч. 2), п. 22 |
| Постороннее лицо в кассовой зоне (`outsider`) | в кассе одновременно ≥ 3 человек, из них ≥ 2 в полный рост (кассир + лишний) | НБРК № 231, п. 75 (по аналогии для кассовой зоны) |
| Дверь кассы не закрыта (`door_open`) | после входа часть помещения у входа остаётся изменённой > 5 с без людей в этой зоне | Правила охраны и устройства помещений (НБРК № 14 от 24.02.2020), п. 16 пп. 1 (во временной редакции, действующей до 01.01.2027) |
| Кассир покинул рабочее место, не убрав ценности в сейф (признаки) (`hasty_exit`) | кассир встал и покинул кабинет за ≤ 3 с, не задерживаясь у сейфа (в норме 4–14 с: убирает ценности и запирает сейф) | НБРК № 231, п. 20 (ч. 2), п. 22 |
| Операция с посетителем проведена без проверок (признаки: слишком короткий визит) (`short_visit`) | посетитель (клиент/инкассатор) уходит через ≤ 10 с — проверка документа и пересчёт при нём маловероятны (в норме визит > 15 с) | НБРК № 231, п. 7, п. 20 (ч. 1) |
| Наличные открыто оставлены на рабочем месте (`cash_exposed`) | к кассе подходит следующий клиент, а на столе уже лежит пачка купюр (OWLv2) | НБРК № 231, п. 20 (ч. 2) |
| Еда или напитки на рабочем месте с наличными (`food_drink`) | стакан с напитком устойчиво стоит на столе кассира (OWLv2, замер каждые 2 с) | НБРК № 231, п. 12 (личные вещи — вне кассового узла), п. 20 (ч. 2) |

Полный разбор 15 типов, найденных в обучающих видео (с парами «норма / нарушение»), — `LABELS.md`.
Нормативная база с дословными цитатами и принципом сопоставления «что видно → почему нарушение → пункт» — `laws/LAWS.md`.

## 5. Качество на обучающих видео (40 уникальных роликов)
| Метрика | Значение |
|---|---|
| Ложные срабатывания на нормальных видео | **0 из 19** |
| Найдено видео с нарушением | **14 из 21** на GPU (все кадры 1/с) |
| Верный вердикт по видео (accuracy) | 82% на GPU |
| Имитация другого ракурса (зеркало + перспектива + темнее) | до правил OWLv2: 8 из 21 найдено, 2 ложных из 19 (оба — правило быстрого ухода); правила OWLv2 на этих копиях ложных не дали, дополнительно поймали X-4 и X-46 |
| Ошибка таймкода (медиана) | ≈ 2 с (8 из 14 найденных — в пределах 2 с) |
| Время обработки видео | **1–13 с на GPU** (ноутбучная RTX 3050), примерно 20–90+ с на CPU; лимит ТЗ — 5 мин |

## 6. Ограничения и известные ошибки
- **Понимаем, но пока не видим:** в X-44 машинка отделила подозрительную купюру, а кассир вернула её в пачку без проверки (П231 п. 41); в X-34 клиент ушёл до конца пересчёта (П231 п. 20 ч. 1); в X-22 ключ оставлен в замке сейфа (П231 п. 76). Это мелкие детали (карман машинки, ключ — несколько пикселей на кадре); для них нужен детектор, дообученный на кадрах банка — подробности в `LABELS.md`.
- Не видит мелкие детали: ключ в замке сейфа, поворот ключа, предъявление удостоверения, купюры в руках.
- Пропущено 7 из 21 обучающих видео с нарушением:
  - X-1 — часть денег вернули клиенту;
  - X-2 — наличные приняты без удостоверения (но удостоверение не видно и на 4 нормальных видео — без ложных тревог это не отличить);
  - X-20 — сейф оставлен открытым;
  - X-22 — ключ оставлен в замке сейфа + ноутбук полузакрыт;
  - X-34 — клиент ушёл во время пересчёта;
  - X-40 — личные вещи (правило есть, но выключено: 3 ложных из 19 — детектор путает с сумками клиентов);
  - X-44 — купюру убрали без проверки подлинности.
- На имитации другого ракурса: 2 ложных тревоги от правила быстрого ухода (`hasty_exit`); X-38 (деньги на столе) не пойман —
  на затемнённом кадре OWLv2 хуже видит пачку купюр.
- Выключенный свет и сильная смена освещения отключают правило двери на эти кадры.
- Люди за стеклянной стеной и отражения отфильтровываются по геометрии кадра — при сильно другом ракурсе возможны ошибки.
- Нельзя установить по видео: сумму операции, проводку, наличие распоряжений — такие выводы сервис не делает.
